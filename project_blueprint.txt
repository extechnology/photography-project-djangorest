1. EXECUTIVE SYSTEM OVERVIEW & NEW CAPABILITIES
===============================================================================
The platform is a multi-tenant photography studio hub, client media delivery
system, and digital asset management engine engineered for high concurrency,
large image/video processing, and secure media sharing.

Key Additions in Version 2.0 (Synchronized with Frontend Atelier UI):
1. Editorial Multi-Template System:
   - Dynamic layout switching across 4 bespoke templates:
     * 'editorial': Fine-art storytelling with hero spreads and dual-column layouts
     * 'masonry': High-density balanced dynamic column grid
     * 'cinematic': High-contrast darkroom display with widescreen ratios
     * 'minimal': Clean whitespace-focused gallery for portraits & luxury fashion
   - Template selection persisted per gallery with live client preview switching.

2. Full Video Asset Support:
   - Seamless coexistence of high-resolution stills and video media items.
   - Embeddable 4K videos (Vimeo/YouTube/Custom HLS CDN) with duration tags.
   - Video thumbnail generation and aspect-ratio metadata extraction.

3. Client Proofing, Favorites & Selective Downloads:
   - Client favorite tagging (hearting items in lightbox and grid).
   - Multi-selection toolbar: "Select All", individual select, count tracking.
   - Selective Bulk ZIP generation: Download only selected media subsets on demand.
   - Client Proofing Submission: Clients submit their selections with notes to the studio.

4. Studio Branding & Automated Watermark Pipeline:
   - Studio profile branding: Studio Name, Bio, Location, Website, Instagram handle.
   - Watermark engine: Configurable watermark text or PNG stamp automatically
     burned onto client-facing previews and web derivatives via Celery/Pillow.
   - Onboarding state tracking for new photographer setups.

5. Tiered Subscription & Billing Quota Engine:
   - Multi-tier subscriptions: 'starter' (50GB), 'pro' (120GB), 'studio' (500GB),
     and 'master' (1TB+).
   - Billing cycle support: Monthly vs. Annual discounting.
   - Real-time committed storage vs. in-flight reserved upload tracking.
   - Feature gating: Layout templates, 4K video, face search, and custom domains.

6. Event Notifications System:
   - Dedicated notification triggers for 5 critical studio milestones:
     * Client visited gallery
     * Photos downloaded (single or ZIP archive)
     * Client favorites / proofing selection submitted
     * Storage quota warning (80% / 90% threshold)
     * Platform updates & studio reports.

5. DIRECT-TO-CLOUD STORAGE & UPLOAD PIPELINE (PHOTOS & VIDEOS)
===============================================================================

Problem Solved:
Directly handling gigabyte-sized photo batches or 4K video uploads through Django
WSGI worker threads causes worker pool starvation, high memory spikes, and proxy
timeouts.

Negotiated Direct-to-Cloud Upload Workflow:

Step 1: Upload Initialization
  - Client sends: POST /api/storage/galleries/{id}/upload-init/
    Payload:
    {
      "files": [
        { "filename": "IMG_9041.CR3", "file_size": 48234496, "mime_type": "image/x-canon-cr3", "media_type": "photo" },
        { "filename": "Highlight_Teaser.mp4", "file_size": 251658240, "mime_type": "video/mp4", "media_type": "video" }
      ]
    }
  - Atomic Quota Check:
    (photographer.storage_used_bytes + photographer.storage_reserved_bytes + total_requested_bytes) <= plan_storage_limit
  - Django creates UploadReservation records (status='pending', expires in 2 hours).
  - Atomically increments photographer.storage_reserved_bytes.
  - Storage Provider signs direct HTTP PUT pre-signed URLs:
    Key: "galleries/{gallery_id}/originals/{media_id}.{ext}"
  - Response returns:
    [
      { "media_id": "...", "reservation_id": "...", "upload_url": "https://bucket.s3.amazonaws.com/...", "storage_key": "..." }
    ]

Step 2: Direct Binary Transfer
  - Client web browser uploads raw binary data directly to the object store (Local / S3) via HTTP PUT.
  - Django servers are completely bypassed during the heavy byte streaming.

Step 3: Upload Confirmation & Background Handoff
  - Client sends: POST /api/storage/galleries/{id}/upload-confirm/
    Payload:
    {
      "media_id": "...",
      "reservation_id": "...",
      "aspect_ratio": 1.5,
      "width": 6000,
      "height": 4000,
      "duration": "00:00"
    }
  - Django updates photographer storage:
    storage_reserved_bytes -= file_size
    storage_used_bytes += file_size
  - Sets Media status to 'processing'.
  - Celery Worker task dispatched: process_media_derivatives_and_faces_task.

6. ASYNCHRONOUS DERIVATIVE, WATERMARKING & MEDIA PIPELINE
===============================================================================

Celery Worker Pipeline: process_media_derivatives_and_faces_task
Triggered on: Successful upload confirmation.

Pipeline Steps:
1. Asset Ingestion:
   - Fetches original file binary from object storage provider.
   - Extracts EXIF data (Camera model, lens, aperture, shutter speed, ISO).
   - Auto-rotates image according to EXIF orientation tag.

2. Thumbnail Generation (Fast 300x300):
   - Generates compact thumbnail max 300x300 px using LANCZOS downsampling.
   - Saves optimized JPEG/WebP at 85% quality.
   - Uploads to: "galleries/{gallery_id}/thumbnails/{media_id}.jpg".

3. Preview Generation & Watermark Application (1200x1200px):
   - Generates web preview bounding box max 1200x1200 px.
   - Checks photographer.enable_watermark:
     * If True and watermark_text is set: renders typographic watermark overlay
       with customized opacity and position.
     * If True and watermark_image is set: blends PNG logo watermark with alpha channel.
   - Saves preview to: "galleries/{gallery_id}/previews/{media_id}.jpg".
   - Note: Original master files ("originals/...") remain 100% untouched and unwatermarked
     for client master downloads.

4. Video Media Handling:
   - If media_type == 'video':
     * Extracts poster thumbnail frame at 1.0 second offset via ffmpeg/Pillow.
     * Computes exact duration and stores in Media model.

5. AI Biometric Face Detection:
   - If gallery.face_search_enabled is True:
     * Scans preview image for faces.
     * Calculates 128-D normalized face embedding vectors.
     * Saves FaceEmbedding rows indexed strictly to gallery.

6. Finalization:
   - Sets media.processing_status = 'ready'.

7. CLIENT PROOFING, FAVORITES & SELECTION WORKFLOW
===============================================================================

Workflow Overview:
Couples and clients review high-resolution proofs in the editorial or masonry
layouts, star their favorites, and submit their final selection for retouching
or album printing.

Step 1: Public or PIN-Protected Access
  - Client accesses gallery via clean slug or UUID:
    GET /api/storage/public/galleries/{slug_or_id}/
  - If is_password_protected: Client enters PIN code.
  - Endpoint verifies hashed password or PIN code and returns a 12-hour client
    session access token.

Step 2: Client Favoriting & Selection
  - Client marks favorites or selects images for album inclusion.
  - Frontend maintains real-time selection state and syncs to backend:
    POST /api/storage/galleries/{id}/client-selections/
    Payload: { "client_email": "couple@wedding.com", "selected_media_ids": ["uuid-1", "uuid-2"] }

Step 3: Selective Bulk Download ("Download Selected")
  - Client clicks "Download Selected (12 Photos)".
  - Client dispatches: POST /api/storage/galleries/{id}/bulk-download/
    Payload: { "download_type": "selected_subset", "media_ids": ["uuid-1", "uuid-2", ...] }
  - Celery compiles a lightweight ZIP containing only the chosen media files.
  - Returns signed download URL when job completes.

Step 4: Selection Submission
  - Client finalizes selections and clicks "Submit Selections to Studio":
    POST /api/storage/galleries/{id}/client-selections/{selection_id}/submit/
    Payload: { "client_notes": "Please retouch bride's veil in photo #4 and make photo #12 black & white." }
  - Selection status changes to 'submitted'.
  - Backend automatically sends studio notification and email to photographer.

8. AI BIOMETRIC FACE RECOGNITION & DISCOVERY ENGINE
===============================================================================

Architecture & Algorithm (FaceService):
1. Face Region Detection:
   - Analyzes uploaded media frames and guest selfie probes.
   - Detects all face bounding boxes (x, y, w, h) and confidence ratings.

2. 128-Dimensional Feature Extraction:
   - Normalizes facial region to canonical 64x64 illumination-adjusted grid.
   - Extracts 64 spatial cell mean intensity distributions and 64 gradient moments.
   - Normalizes vector to unit length (L2 norm).

3. Biometric Search Execution:
   - Guest uploads reference selfie: POST /api/storage/galleries/{id}/face-search/
   - FaceService computes 128-D probe vector from selfie.
   - Fetches FaceEmbedding vectors for the gallery.
   - Computes cosine similarity: dot(probe_vector, candidate_vector).
   - Media items with similarity >= 0.65 are ranked and returned.

4. Biometric Privacy Protection:
   - Vectors are stored strictly as internal database records.
   - Embeddings are NEVER exposed in any REST API serializer or client response.
   - Biometric search is strictly isolated per gallery.

9. SECURITY, AUTHENTICATION & ACCESS CONTROL ARCHITECTURE
===============================================================================

1. Authentication Protocols:
   - JWT (SimpleJWT): Bearer <access_token> with 60-minute lifetime and rolling refresh.
   - Multi-Identifier Authentication: Login via Username, Email, or Phone number.
   - Transactional OTP: 6-digit codes with 10-minute expiry windows for password reset & registration.
   - Google OAuth2 token exchange endpoint for one-click studio login.

2. Enterprise Gallery Security:
   - Cryptographic Share Tokens: 32-byte URL-safe tokens (256 bits entropy).
   - Token Revocation: Instant re-generation invalidates previously shared links.
   - Gallery PIN / Passwords: Securely hashed with PBKDF2/Argon2.
   - Expiration Controls: Automatic expiration timestamps return HTTP 410 Gone.

3. Media Download Protection:
   - Original master files are strictly private in object storage.
   - Downloads are delivered via time-limited signed URLs (valid 15 minutes).
   - Prevents public hotlinking and direct bucket crawling.
